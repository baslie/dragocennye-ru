# Test Specs: Catalog Browse

Эти спеки **framework-agnostic** — адаптируйте под свой стек (Jest, Vitest, Playwright, Cypress, RTL).

## Overview

Catalog Browse — листинг камней с табами видов, тонкой строкой live-фильтров, сортировкой, пагинацией
(12 на страницу) и empty-state. Проверяем фильтрацию, навигацию, пагинацию и пустую выборку.

---

## User Flow Tests

### Flow 1: Фильтрация по виду и цвету

**Scenario:** Пользователь сужает каталог до зелёных сапфиров.

#### Success Path

**Setup:**
- `varieties` содержит «Сапфир» (`v-sapfir`, stoneCount 52), `colors` содержит «Зелёный».
- `stones` — наполненный массив (см. `sample-data.json`), таб «Все» активен (`filters.varietyId === null`).

**Steps:**
1. Пользователь открывает `/catalog`.
2. Видит ленту табов с «Все» (активен) и карточками видов с подписью + счётчиком.
3. Кликает таб «Сапфир».
4. Открывает чип «Цвет», выбирает «Зелёный».

**Expected Results:**
- [ ] Клик по табу вызывает `onSelectVariety('v-sapfir')`.
- [ ] Появляется `SeoBlock` с H1 «Сапфиры» и описанием вида.
- [ ] Клик по «Зелёный» вызывает `onFilterChange` с `colorIds`, включающим зелёный.
- [ ] Сетка перерисовывается без перезагрузки; счётчик найденных в строке фильтров обновляется.
- [ ] Кнопки «Применить» нет — фильтрация мгновенная.

#### Failure Path: Комбинация без результатов

**Steps:**
1. Пользователь выбирает фильтры, под которые не подходит ни один камень.

**Expected Results:**
- [ ] Вместо сетки рендерится `EmptyState` с текстом «Камней по вашему запросу не нашлось».
- [ ] Видна кнопка «Сбросить фильтры» (coral).

---

### Flow 2: Сортировка и пагинация

**Scenario:** Пользователь сортирует по цене и листает страницы.

**Steps:**
1. Пользователь меняет сортировку на «Цена ↑».
2. Нажимает «2» в пагинаторе.

**Expected Results:**
- [ ] Смена сортировки вызывает `onSortChange('price-asc')`.
- [ ] Клик по странице вызывает `onPageChange(2)`.
- [ ] Отображается следующая порция (12 камней), страница плавно скроллится к началу сетки.

---

### Flow 3: Переход к камню

**Steps:**
1. Пользователь кликает карточку «Оранжево-розовый сапфир Падпараджа».

**Expected Results:**
- [ ] Вызывается `onStoneClick('st-0101')`.
- [ ] (Реализация) происходит переход на Stone Detail по slug камня.

---

## Empty State Tests

### Primary Empty State (фильтры)

**Setup:** `stones` после применения `filters` пуст (`[]`).

**Expected Results:**
- [ ] Виден заголовок «Камней по вашему запросу не нашлось».
- [ ] Видна кнопка «Сбросить фильтры».
- [ ] Клик по кнопке вызывает `onResetFilters()`.

---

## Component Interaction Tests

### StoneCard

**Renders correctly:**
- [ ] Отображает название камня (например «Оранжево-розовый сапфир Падпараджа»).
- [ ] Показывает вес и цену в mono («3.88 ct», «58 200 ₽» с неразрывными пробелами).

**User interactions:**
- [ ] Клик по карточке вызывает `onStoneClick` с id камня.
- [ ] Hover: лёгкий подъём (`-translate-y-0.5`), цена перекрашивается в coral `#FF7444`.

### VarietyTabs

- [ ] Первый таб — всегда «Все».
- [ ] Активный таб подсвечен steel `#576A8F`; hover — coral.
- [ ] На mobile лента табов скроллится горизонтально.

### FilterBar

- [ ] Чипы: Цвет, Огранка, Вес, Цена, Происхождение, Обработка, Сертификат.
- [ ] Справа — дропдаун сортировки и счётчик найденных камней.
- [ ] На mobile сворачивается в кнопку «Фильтры» → bottom-sheet.

---

## Edge Cases

- [ ] Корректно работает с 1 камнем и с 100+ камнями.
- [ ] Длинные названия камней не ломают сетку (truncation/перенос).
- [ ] Переход с пустой выборки в наполненную после «Сбросить фильтры».
- [ ] URL отражает выбранный вид/цвет и номер страницы (`/catalog/sapfir/zelyonyy?page=2`).

---

## Accessibility Checks

- [ ] Табы и чипы доступны с клавиатуры.
- [ ] Дропдаун сортировки управляется клавиатурой.
- [ ] Карточка камня — один кликабельный элемент с доступным именем.
